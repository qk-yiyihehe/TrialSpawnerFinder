# 查找器架构

仓库采用单一开发入口、多算法模块的结构。各查找器源码互不依赖，只把语义完全一致的基础定义放进公共模块；最终发行版仍计划交付一个可执行 JAR 和一个 `run.bat`。

## 当前模块

### finder-core

纯 Java 公共模块，不依赖 Fabric 或 Minecraft 服务端。目前包含：

- `AreaShape`：外层圆形和方形搜索范围。
- `SearchBounds`、`SearchArea`：搜索边界与世界边界裁剪。
- 少量已经由多个算法确认可复用的坐标定义。

### geode-finder

纯 Java 紫水晶模块，不依赖 Fabric、Minecraft 服务端或试炼密室代码。目前负责：

- Minecraft 1.19+ 晶洞起点与纯石头紫水晶母岩模拟。
- 1.21.4及以前按玩家到区块中心严格小于128方块统计活动区块。
- 1.21.5+ 按 simulation distance 统计活动区块。
- 圆形/方形外层搜索、世界边界裁剪、并行滚动窗口粗筛和有界 Top K。
- 按真实活动区块精算晶洞起点数和理论母岩数。

该模块可以被未来的独立命令行入口直接调用，不要求进入游戏。

### TrialSpawnerFinder 根项目

根项目保留试炼密室专属逻辑，同时作为当前唯一的 Minecraft 1.21.1 开发验证环境。`finder.properties` 中：

- `finder-type=trial-spawner` 运行试炼密室查找器。
- `finder-type=geode` 运行紫水晶查找器。

紫水晶的全区域粗筛和纯石头精排全部在 `geode-finder` 中完成。只有开发阶段需要核对真实世界生成时，根项目才启动一次 1.21.1 服务端：先选取理论前 N 名，合并并去重所需区块，每个区块只生成和扫描一次，再按实际母岩数重新排序后停服。

## 发行与扩展原则

- 当前只维护一套 Gradle/Fabric 开发环境和一个 `run.bat`，不为每个算法复制运行工程。
- 最终发行版把公共核心和各查找器打进同一个独立可执行 JAR，通过配置选择功能。
- 海底神殿、女巫小屋等后续功能各自建立源码模块，不调用试炼密室或紫水晶的专属实现。
- 只有至少两个查找器已经出现相同需求时，才把分片、进度或 Top N 等实现下沉到 `finder-core`。
- 是否需要 Minecraft 真实生成由具体功能决定；只依赖结构放置或纯算法的功能不启动游戏。
